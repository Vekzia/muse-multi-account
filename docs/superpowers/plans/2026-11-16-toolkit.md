# Muse Launcher Toolkit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development or executing-plans to implement task-by-task. Steps use checkbox syntax.

**Goal:** 完成账号整理、快速入口、网页工具、控制器拆分和 CI。
**Architecture:** 在现有 AppCompat 中按独立控制器拆分，MainActivity 只接入契约。共享文件由集成者持有，模块工作者只编辑分配文件。
**Tech Stack:** Java 17, Android API 29–34, AndroidX WebKit 1.12.1, JUnit4, Gradle 8.10.2.
**Spec:** docs/superpowers/specs/2026-11-16-toolkit-design.md

## Global Constraints
- minSdk 29，compileSdk/targetSdk 34，Java 17；旧账号 JSON 保持兼容。
- 新增触控区域至少 48dp，原生深色界面，敏感凭据不写入日志。
- 不上传 Cookie、代理凭据、debug keystore 或本地索引。
- 共享 MainActivity/manifest/主布局/build/README 由集成者修改，代理各自资源独立文件。

### Task 1: Account organization
Files: Account.java, AccountJsonCodec.java, AccountsStore.java, new AccountOrdering.java, AccountRenderer.java, values/organization_strings.xml, tests AccountOrderingTest/AccountsOrganizationTest.
Interfaces: Account group:String, pinned:boolean, lastUsedAt:long. AccountOrdering.select(List<Account>, String query, String group, String sort) returns new List (null group=all, empty=ungrouped); store getSortMode/setSortMode, assignGroup, setPinned, renameGroup, deleteGroup, moveBefore, markUsed. Renderer consumes Activity/store/rail/list/search and callbacks select/configure/delete/shortcut.
- [ ] Write migration, ordering, search/group and movement tests; run focused tests and record expected red.
- [ ] Implement fields/codec/copy/import and store ordering APIs, retaining old defaults.
- [ ] Implement AccountRenderer with filter controls, accessible action menu, groups, pin and drag/manual movement.
- [ ] Run focused tests and compile; review no lost account IDs after import.

### Task 3: Page tools
